## 파일과 접근 확인

- 영상: 90.000초, H.264, 1920×1080, 24fps, 2,160프레임, 음성 없음. 전체 디코딩과 인코딩된 10개 장면 시각 검토. 실제 APK 실행 캡처 편집본이며 연속 조작 녹화가 아니다.
- 영상 원본 캡처는 기존 공개 실행 검사 캡처와 해시가 같다. 앱 화면은 비율을 유지해 배치하고 외부 설명만 추가했다.
- 기획서: 9쪽 전체 렌더링·시각 확인. 공식 운영정보·동의/서명 표 보존, 문서 작성자 메타데이터 공란, 주석 없음.
- APK: Android 9 이상, versionCode 102, 해시는 아래와 같다. 공개 다운로드한 파일이 기존 검증 대상과 같은 바이트임을 확인했다. 새 서명 검사를 수행했다는 뜻은 아니다.
- ZIP: 포함 기획서와 단독 기획서의 바이트 일치, 압축 무결성, 현재 영상·APK 고정 링크 대조. 이메일 파일은 미발송 초안이다.
- 공개 저장소에는 소스와 apk/의 APK가 있다. 파일 목록에서 개인 서명키·암호 파일을 찾지 않았다. 소스의 서명 설정은 환경 변수 이름이며 암호값이 아니다.
- 제출 문서 본문과 캡처에 참가자 연락정보를 넣지 않았다. 공개 GitHub 주소·프로필·커밋 작성자 정보는 추적 가능하므로 완전한 익명성을 보장하지 않는다. 별도의 개인정보 확인 항목으로 남긴다.

## 공식 안내와 제출 상태

공식 안내는 작성·서명한 접수양식을 필수로 두며 영상·GitHub·APK는 선택 가산점 자료다. 목업·프로토타입·화면 녹화를 인정하고 세부 배점은 공개하지 않는다. 따라서 SDK 미연동이나 고객 실측 부족을 숨기지 않고 현재 개발 수준을 정확히 제출한다. 이 감사는 1차에 필요한 설명과 자료에 집중한다.

| 남은 항목 | 현재 상태 |
|---|---|
| 개인/팀·부문·대표자·연락처·인원·작성일 | 미기입. 실제 참가정보 필요 |
| 참가자별 동의·본인 서명·날짜 | 미완료. 팀이면 전원 작성 및 제출 메일 CC 필요 |
| APK 파일명 `팀명_앱이름_release.apk` | 현재 CareRoute_CareRoute_release.apk. 실제 참가 명칭과 맞는지 확정 필요 |
| 제출용 링크와 첨부 선택 | ZIP은 준비 자료. 작성·서명한 공식 양식과 현재 선택 자료를 대조한 뒤 제출 |

| 정성평가 근거 | 실제 허용 위치·SDK 연동·고객 편익·시설 지불 의사 미검증. 접수 필수 항목과 구분 |
